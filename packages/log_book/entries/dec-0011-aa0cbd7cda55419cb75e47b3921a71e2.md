## Decision: requirements live in two Capella requirement modules under Operational Analysis

**Decided by the engineer**, who created the modules in Capella 6.1 and pushed them. This settles one of the gaps in DEC-0010 (where the requirements go in the model).

**State of the model after pulling** (repo `tkSDISW/k-cup-coffee-machine`, branch `master`, commit `c3152cc`, committed 2026-11-23, 11:23 US Eastern; previous check was `304e8a6`)
| Module | Type | UUID | Parent | Draft it will hold |
|---|---|---|---|---|
| Base User Requirements | CapellaModule | `5f1d7c89-97d2-4721-9e9a-073746fbacd9` | Operational Analysis | base requirements (UR-B, NOTE-0003) |
| Reach Requirements | CapellaModule | `99bd934c-7d7d-43e0-9a67-4699c3d7b83a` | Operational Analysis | goal (reach) requirements (UR-G, NOTE-0004) |

- **Both modules are empty:** browsing OA requirements returned none.
- **Nothing else has changed in OA:** there are still no operational entities.
- SA, LA and PA were not browsed in this check.

**Consequences**
- The two modules mirror the base and goal split in the drafts. The names differ slightly from the drafts ("Reach" for the goal requirements); the drafts' IDs (UR-B, UR-G) stay as they are unless the engineer wants them aligned.
- Placing both under OA matches the paper's guidance to keep need-originated requirements apart from solution requirements (DEC-0010 checklist item 6). Solution requirements, when they arise, would go in a separate module.

**Open items**
1. **When to populate the modules.** The engineer is reviewing the drafts in detail, so they are not written to the model yet.
2. **How to populate.** Two routes: create requirement objects in Capella directly, or add them through `capella-fabric` patches. Whether `apply_model_patch` can create requirements inside a module on 6.1 is untested and will be recorded as a compatibility finding (the Handbook `mcp_tools` package should be read first).
3. **Identifier and field mapping.** Decide how UR-B and UR-G IDs, the requirement statement, rationale, capability link, verification method and evidence tag map onto Capella requirement fields (for example prefix, long name and text), and where the threshold and goal values are held (DEC-0010 gaps).
