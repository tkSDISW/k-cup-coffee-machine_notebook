## Compat finding 3: creating a requirement inside a requirement module by patch (first write test, local commit)

**Result:** the patch applied and committed. **Pending:** the engineer's check in Capella 6.1 after push, and three small observations below.

1. **Tool and calls**
   - `verify_model(phase="OA")` before and after the patch: no findings either time (0 issues).
   - `apply_model_patch(author_name="Claude Coffer Maker", commit_message="Add draft requirement UR-B-04 (coffee preparation cycle time) to Base User Requirements module", patch_yaml=...)` with:
     ```yaml
     - parent: !uuid 5f1d7c89-97d2-4721-9e9a-073746fbacd9
       extend:
         requirements:
           - name: UR-B-04
             long_name: Coffee preparation cycle time
             text: "The coffee preparation cycle time shall be defined and bounded: (a) from request to coffee available at serving temperature when the system is ready (TBD); (b) from a cold or idle start (TBD); (c) between consecutive servings (TBD)."
     ```
   - Then `browse_model(phase="OA", object_type="Requirement")`, `resolve_model_uuids`, and `generate_fabric` to read the result back.
2. **Context:** Capella 6.1 model `K Cup Coffee Maker.aird`; commit before `c3152cc`; local commit after `0afe0269` (**not pushed**). Target: CapellaModule "Base User Requirements" (`5f1d7c89-97d2-4721-9e9a-073746fbacd9`), created by the engineer in Capella 6.1. New element: Requirement `UR-B-04`, UUID `d3a7b156-986c-43e0-b9df-019d4ba8a963`.
3. **Expected vs actual**
   - Expected: one requirement created in the module. Actual: patch status `ok`, commit status `committed`. The requirement appears with the name, long name and text exactly as written. `prefix` and `chapter name` are empty and `requirement_type` is None, since none were set.
   - **Observation A, scope note:** the tool's own description limits creation to structure, functions, activities and OA interactions, and does not list requirements. The patch worked anyway, so requirements via `extend: requirements:` under a module are at least accepted on this model.
   - **Observation B, containment not visible:** `browse_model` and `resolve_model_uuids` show `layer` and `parent` as "—" for the requirement, and `generate_fabric` does not show containment. The tools therefore cannot confirm that the requirement sits inside the intended module. Confirmation has to come from Capella.
   - **Observation C, module name:** `browse_model` shows the module's name as "Base User Requirements", while `generate_fabric` lists its `name` as empty with an empty description. It is not clear which field holds the displayed name (for example a long name); worth a look when mapping requirement fields.
4. **Reproduction:** clone at commit `c3152cc`, run the `apply_model_patch` call above against the module UUID, then browse requirements and run `generate_fabric`.
5. **Scope:** unknown. Nothing so far points to 6.1 specifically; the 7.0.1 suite may already cover requirement creation.
6. **Workaround:** not needed so far.
7. **Check in Capella 6.1:** **pending.** The commit is local; the engineer will check that the requirement appears inside "Base User Requirements" with the right text and that the model opens normally once the change is pushed.
8. **Tool version or build:** not known (open item in DEC-0007).

**Not yet covered:** `pull_model_changes` in a live session, `push_model_changes`, setting `prefix`, requirement type and other fields by patch, and creating requirement folders or links to model elements.
