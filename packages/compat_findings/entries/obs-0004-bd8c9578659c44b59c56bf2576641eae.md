## Compat finding 4: batch creation of requirements and operational capabilities by patch, `set:` on an existing requirement, and `pull_model_changes` (local commits)

**Result:** all operations were accepted and committed locally. **Pending:** the engineer's check in Capella 6.1 after push. Two observations about what the read-back tools can and cannot show.

1. **Tool and calls**
   - `pull_model_changes(session_id)` before the patches.
   - `apply_model_patch` with two `parent:` entries in one patch, each using `extend: requirements:` under a requirement module (3 requirements under "Base User Requirements", 12 under "Reach Requirements"), each with `name`, `long_name`, `text` and `description`.
   - `apply_model_patch` with `parent: !uuid <requirement>` and `set: description:` on the existing requirement UR-B-04.
   - `apply_model_patch` with `parent: !uuid e98f0aa8-6701-4804-adc3-d30d80ce6bb3` (Operational Capabilities package) and `extend: capabilities:` with 12 entries, each with `name` and `description`.
   - Read-back: `browse_model` for `Requirement` and `Capability` (OA), `resolve_model_uuids`, `generate_fabric`, and `verify_model(phase="OA")`.
2. **Context:** Capella 6.1 model `K Cup Coffee Maker.aird`. Model commit at the start: `0afe026` (the pushed UR-B-04 commit). New local commits: `74a894bd` (15 requirements), `c0ad724e` (UR-B-04 description), `c742d25b` (12 capabilities). **None of the three is pushed.**
3. **Expected vs actual**
   - `pull_model_changes` returned `up_to_date` with commit `0afe026` and no incoming or local commits. Only the "up to date" outcome was exercised.
   - **Batch requirement creation:** status `ok`, committed. `browse_model` lists 16 requirements in total (4 base, 12 goal).
   - **`set:` on an existing requirement:** status `ok`, committed.
   - **Capability creation:** status `ok`, committed. `browse_model` lists 12 `OperationalCapability` elements with parent "Operational Capabilities". This works although the tool's own description limits creation to structure, functions, activities and OA interactions and does not list capabilities.
   - `verify_model(OA)`: no findings (0 issues) after the patches, as before.
4. **Observation A, requirement description not visible:** `generate_fabric` shows `text`, `plain text`, `long name`, `prefix`, `chapter name` and `requirement_type` for requirements, but **no `description`**. For capabilities, `description` is shown. So the `description` values written to requirements (including the `set:` on UR-B-04) **cannot be confirmed from the tools**; the engineer's check in Capella is needed.
5. **Observation B, containment still not visible** (carried from Compat finding 3): requirements show layer and parent as "—", so which module owns each one cannot be confirmed from the tools.
6. **Observation C, characters in text:** one description contains an apostrophe (UR-G-09). The Handbook says descriptions are HTML content and that encoded characters look double-escaped in the raw file; check it displays correctly in Capella.
7. **Reproduction:** clone at commit `0afe026`, pull, apply the three patches above in order, then run the read-back calls.
8. **Scope:** unknown; nothing so far points specifically to 6.1. Requirement and capability creation may already be covered by the 7.0.1 suite.
9. **Workaround:** none needed.
10. **Check in Capella 6.1:** **pending** after push. To check: all 16 requirements sit in the right modules (4 base, 12 reach); long names, text and descriptions display correctly (including the apostrophe in UR-G-09's description); the 12 capabilities appear in the Operational Capabilities package; and the model opens without warnings.
11. **Tool version or build:** not known (open item in DEC-0007).

**Not yet covered:** `pull_model_changes` when commits are incoming or when the session has diverged; creating links between requirements and model elements; setting `prefix`, requirement type and other requirement fields; creating requirement folders; creating operational entities, activities and scenarios on 6.1; pushing the three local commits.
