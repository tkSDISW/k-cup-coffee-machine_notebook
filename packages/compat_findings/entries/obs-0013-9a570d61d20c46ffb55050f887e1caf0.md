## Compat finding 13: an idle model session expires, and the error does not say so; resuming works (confirmation with a suggestion)

**Result:** worked as expected after a fresh clone. One suggestion for the error text.

1. **Tool and calls:** `pull_model_changes(session_id=<session from the previous day>)`, then `clone_capella_repo(repo_url=..., branch="master", agent_id=<registered agent>)` with no credential.
2. **Context:** Capella 6.1 model `K Cup Coffee Maker.aird`. The earlier session had been idle for about a day (sessions are swept after roughly 4 hours of inactivity, per the server's own instructions). The new session opened at commit `cb4e327` (committed in Capella 6.1 by the engineer).
3. **Expected vs actual**
   - `pull_model_changes` on the old session returned an error: `[Errno 2] No such file or directory: '/tmp/capella_fabric/<session id>/session.json'`. It does not mention that the session has expired.
   - `clone_capella_repo` with only the agent id resumed from the stored GitHub authorization, with no browser trip, and returned a new session id.
4. **Suggestion to the tool maintainer:** a tool call on an expired or unknown session could return a message such as "unknown or expired session; open a new one with clone_capella_repo" (as `knowledge-repo` does with "Unknown session_id"), instead of a file-system error.
5. **Reproduction:** leave a session idle for more than the sweep interval, then call any tool with its session id.
6. **Scope:** none observed; unrelated to the Capella version.
7. **Workaround:** re-clone, which is free for a repo connected through GitHub.
8. **Check in Capella 6.1:** not applicable.
9. **Tool version or build:** not known (open item in DEC-0007).
