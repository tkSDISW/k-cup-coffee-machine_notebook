## Compat finding 8: creating a requirement link from the model-element side is refused (nothing committed)

**Result:** the patch was refused with a clear error. **No commit was made.** The model is unchanged by this test.

1. **Tool and call:** `apply_model_patch` with the capability as parent, adding the requirement through the element's `requirements` property:
   ```yaml
   - parent: !uuid 74ad58bb-90ae-4017-99ae-f41510b8681b
     extend:
       requirements:
         - !uuid b9ec03d9-dc96-43dd-a29d-9980479f0ab3
   ```
   (capability "Obtain ready-to-use coffee supplies in variety", requirement UR-B-01).
2. **Context:** Capella 6.1 model `K Cup Coffee Maker.aird`; model at commit `85b33268` (pushed). No new commit resulted.
3. **Expected vs actual:** expected the link to be added the way `extend: involved_entities:` adds an entity (Compat finding 6). Actual error: `Cannot insert objects into <ElementRelationAccessor 'ModelElement.requirements'>`. The `requirements` property on a model element is readable (it lists related requirements) but cannot be written to.
4. **Why it matters:** the engineer's convention (DEC-0015) is that links point from the model element to the requirement with a satisfy relationship. The only creation path found so far starts from the requirement's side (Compat finding 7), and its direction and relation type cannot be read back from the tools.
5. **Reading related requirements:** `generate_fabric` does not list a capability's `requirements`, even though the property exists, so the capability side of a link is also not visible in the read-back.
6. **Reproduction:** open a session at `85b33268` and run the patch above.
7. **Scope:** unknown; the error comes from the library accessor and is not obviously specific to 6.1.
8. **Workaround:** none by patch so far. Links can be drawn in Capella.
9. **Check in Capella 6.1:** not applicable (no change). The check of the UR-B-04 link from Compat finding 7 is still pending.
10. **Tool version or build:** not known (open item in DEC-0007).

**Request for the tool maintainer, as a suggestion:** support creating requirement relations in the element-to-requirement direction, with a relation type such as satisfy, and show a relation's source, target and type in the read-back (`generate_fabric` or `browse_model`).

**Not yet covered:** other patch shapes for creating relations (for example `relations:` with an explicit `_type: CapellaIncomingRelation` and a requirement as target, set from the element side), and relation types.
